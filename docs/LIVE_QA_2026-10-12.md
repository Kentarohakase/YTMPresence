## Initial observations and fixes

| Check | Observation |
| --- | --- |
| A playing, B paused/in front | Discord continued to show A with artist and advancing progress. |
| Both test tabs paused | Discord's YouTube Music activity disappeared with `OnlyShowWhenPlaying=true`. |
| B starts while A is paused | The mini player received B's title and subsequent autoplay titles. |
| Mini-player pause | B paused, but A and the existing paused tab also started. The user subsequently confirmed the Web Store installation was active. This is consistent with the old broadcast behavior and does **not** validate the new single-tab routing. Load the unpacked repository extension before the routing retest. |
| Autoplay timing | On **Kado & Promoting Sounds - Shades of Blue**, YouTube Music showed **0:55 / 2:22**, while the underlying video reported approximately **225.42 / 311.766 seconds**. The mini player exposed that cumulative timeline as **3:45 / 5:11**. |

The time mismatch is reproduced by a regression test that failed before `839d7cd` (`225.42 !== 55`). The extension now prefers finite, coherent, visible player-bar progress in seconds, retaining the media-element fallback when that source is absent or invalid. Tests also cover track changes, seeks, zero position, invalid values and hidden controls.
