Connection regressions distinguish an open socket from an accepted token. They cover unsaved inputs, missing or invalid settings, storage failure, save/event idempotency, wrong tokens, socket construction/error/close, connection/authentication timeouts and bounded retry delays. They also check overlapping saves, token changes during a check, old socket open/error/reply callbacks, optional or mismatched versions, paused-track replay and keepalives without playback replay. The Core keepalive regression checks that a paused track and its last-playback timestamp remain unchanged. Existing Core tests continue to accept legacy playback messages without a preceding version-aware handshake.

UI tests run the shared status renderer and options/popup scripts against browser/DOM fixtures. They check consistent states and next steps in both languages, installation-type mapping (including unknown/failure), unsaved-change notices, background-only save/check messages, recovery from failed responses and unchanged permissions. Layout and keyboard behavior require live browser checks.
